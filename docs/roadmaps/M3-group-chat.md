## 待决策

- R3.1:唤醒词初始表、匹配方法、时区;睡眠期间是否记录群消息尚未指定,不能把静音的“不记录”扩大为睡眠规则;确定性门控与全部参数配置是 §7.3 推论,需确认。旧禁用群设置、群防抖、拆句、表情与自动引用的取舍仍待定(§7.3、§11.6、§12.3)。
- R3.2:每小时抽样时点、重启补抽、冷却起算与失败语义、非静音未处理消息是否缓冲及缓冲范围;“其他成员回复”指引用、@ 还是任意后续消息,续聊是否免 @+关键词、无人回复期限(§7.2–§7.3、§12.3)。
- R3.3:静音词表、触发者权限、重复闭嘴是否延长、与在途请求/总结竞态的处置;§7.3 对静音记录的旧疑问已由 §12.1“不记录”明确覆盖。
- R3.4:按群独立的具体会话单位、参与者与续聊范围、超时和最大轮数、睡眠到点的活跃轮处置、重启恢复;群会话是否也走 8 小时压缩未定(§7.1、§7.3、§12.3)。每群持久状态及字段 `last_proactive_at`、`muted_until` 是候选方案,不是已定结构。
- R3.5:群 SKILL 用 JSON 卡还是 SKILL.md、merge/format/parse 的采纳与缺陷修正、总结档位是否 low、版本化/人工覆盖、画像抽取与容量/保留规则(§7.3、§11.7、§12.1b)。

## 与其他阶段的接口

- M1 提供范围白名单、QQ 消息、模型与工具循环、调度;模型用途为群聊 low(§12.1)。
- M2 提供记忆可见域硬过滤;M3 只产生群内处理会话的材料。旧私聊“模糊摘要”不能作为群聊输入。
- R3.2 向 R3.4 提交主动开场请求,R3.4 定义续聊状态并消费 R3.3 静音信号,结束材料交 R3.5;R3.5 是 R3.4 结束处理的下游,不反向阻塞生命周期规格拆解。
- M6 微信只做私聊且后置,不对接本子系统;旧群日报与全天技能卡取舍不在本阶段暗中迁入。
