## 待决策

- 配置格式、字段路径、重载语义、好友判定来源与白名单边界（§3、§12.1—§12.2；R1.1/R0.2）。
- 适配器纯转换边界、统一消息字段及首期消息段/动作集合仍为推论，不能把旧插件全部动作视为首期已定需求（§9、§11.2；R1.2）。
- 陌生人处理、身份持久化与入口唯一性细则；群消息不进入私聊总会话的具体存储隔离仍需确认（§4、§7.1；R1.3/R1.4）。
- 聊天图片：引用消息中的图片尚无取回路径；上游对 `input_image` 的真实接受、NapCat 真实图片地址可下载性、默认取值（最近 3 个带图轮次、长边 1536、每范围 200 张/30 天）待用户确认（§13.2b；R1.8）。
- 追加日志、摘要与尾部、原始记录保留、工具输出截断/落盘仍为 §5.2 推论；SQLite 在 §12.1b 是记忆存储建议，会话采用 SQLite 需单独确认（R1.4）。
- 主 Agent 统一 Responses 是 §13.6c 推论；Codex 上游原生 Responses、gateway 不翻译则已定，不可混淆（R1.5）。
- reply 多次调用、普通文本内部处理、沉默与错误、身份约束与工具结果形态（§6；R1.6）。
- 系统事件载荷、队列持久化/恢复、并发顺序、交付语义及空闲计时口径尚未定（§6、§10、§13.7；R1.7）。

## 与其他阶段的接口

- [M2](M2-private-chat.md) 接输入状态与运行控制：最后一次正在输入推送后 5 秒、无最长等待上限；无工具调用时新消息打断重开，有工具时经结果注入；50% 窗口压缩、8 小时空闲主动压缩。
- [M3](M3-group-chat.md) 独立实现群门控/会话；范围白名单不替代睡眠、静音等群规则，群隐私不得流入错误可见域。
- [M4](M4-voice.md) 通过媒体消息与发送接口接客户端，不修改 SoVITS/ASR 服务端。
- [M5](M5-coding-agent.md) 通过工具与系统事件接 codex_* / omp_*，两族分开，彻底放弃 legacy。
- [M6](M6-later.md) 承接微信、通知最常用入口、旧功能取舍及授权上线；M1 不提前实现通知统计。
