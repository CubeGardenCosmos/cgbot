## 通知投递：私聊回合总结（R5.4 通知，离线）

- 变更:Coding Agent 通知不再以 `[Coding Agent] …` 正文直接发到私聊。`QqNotifier.notify` 依次:① 有附件时单独发送附件消息(无文字);② 把通知记为私聊会话的 `system_event`,其 `item` 为模型可见的系统通知(正文截断至 1500 字,附件仅列文件名、不含 URL,末尾要求用一两句人设口吻总结、不复述原文);③ 调用回合触发器 `App._start_coding_notice_turn`,经 `PrivateDispatcher.on_wake`(`item=None`)排入私聊 lane。触发回合等待正在运行的回合与 5 秒安静窗口后执行、不打断正在运行的回合,输入即已记录的通知,不再追加 user 项。
- 回退:记录或触发失败时,直接发送纯文本 `[Coding Agent] {类别}：{标题}`,附 `状态：…` 行(等待输入时附 codex_steer 提示),不含正文;日志只记 kind 与异常类型。附件发送失败不阻止记录与触发,记录的 `files_delivered` 为 False。
- 取代:上文第 43 行旧的"不含正文,不进入模型上下文"描述,以及旧的"通知模型可见性"用例(直接文本通知、4000 字发送上限)已过时。`on_wake` 现返回 bool:关闭中返回 False,供触发器判定丢弃。
- 已知限制(推论,未验证):通知记录写入时若另一回合正在运行,该回合之后的请求可能已读到该通知,触发回合随后可能再次总结同一条通知。
- 测试:`tests/coding_app/test_coding_app_notifier.py`(文本通知不直发正文、附件、附件发送失败、触发失败回退、记录失败、发送异常、目标映射)、`tests/coding_app/test_coding_app_notice_visible.py`(模型项截断、附件无 URL、等待提示)、`tests/dispatch/test_dispatch_wake.py`(`item=None` 回合不新增 user 项、运行中排队不取消、关闭后返回 False)、`tests/app/test_app_coding_notice.py`(端到端由私聊回合总结且不直发;会话与用户校验)。
