## 完成证据

推论（代码与测试已落地，待 Lead 验收）：
- 反向 WS 服务端监听 `/ws`，握手要求 `x-self-id`（缺失或非数字 400），路径错误 404，配置 token 时 `Authorization: Bearer` 不符 401；同一 self_id 新连接替换旧连接。
- 未知段保留为 `other`（携带 `onebot_type`）；字符串（CQ 码）消息丢弃；消息 ID、引用 ID、用户/群 ID 统一转 str。
- 入站 input_status 缺 `time` 时用接收时间；空 `status_text` 原样交出，不视为停止。
- 动作请求以 uuid echo 关联，支持乱序应答；超时/未连接/NapCat 非 ok 返回 `SendResult(ok=False)`，不抛出。
- 多连接时 send/call 使用最后注册的连接；消息分发按连接顺序串行，避免 handler 等待动作应答时死锁。

单元测试（`uv run pytest tests/napcat`）：52 passed。覆盖 U01（数组样例顺序/来源/发送者/引用 ID 不混淆、出站动作构造）、U02（输入中与空文本 input_status 保留字段且不产生停止事件）、握手+lifecycle、私聊消息、echo 乱序关联、超时、未连接、401 鉴权、替换连接、断线挂起调用失败。
