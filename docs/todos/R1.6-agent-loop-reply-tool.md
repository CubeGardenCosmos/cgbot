## 测试用例

- R1.6-U01（离线单元）：前置条件：模型只输出普通文本；动作：完成一轮；可观察结果：入口发送次数为零，内部处理按确认策略记录。
- R1.6-U02（离线单元）：前置条件：带来源/消息 ID 的上下文；动作：调用 reply，分别省略目标及指定引用；可观察结果：默认回来源，引用精确交给发送接口，不接受不存在/越归属目标。
- R1.6-U03（离线单元）：前置条件：工具调用成功、失败和无 reply 三类轮次；动作：继续或结束模型循环；可观察结果：结果关联正确，沉默与错误可区分，没有模型文本自动兜底外发。
- R1.6-I01（真实边界集成）：前置条件：获授权的真实上游与好友 QQ；动作：模型调用 reply 引用来信；可观察结果：真实 QQ 收到工具发送内容与正确引用，模型普通文本不额外发送。
- R1.6-C01（检查/平台）：前置条件：循环与工具契约；动作：核对输入中/steering 接口和工具边界；可观察结果：R2.1 可阻止输入中请求，R2.2 可识别是否调用工具；未引入 DSH 或后端无关任务工具层。

## 待决策

- 推论：普通文本以 `assistant` 行存储并标记 `internal: true`，永不外发；展示边界未定（§6）。
- 推论：reply 的 `quote` 只能引用本轮来源消息；`message_id` 必须等于来源消息 ID，其余 ID 拒绝（§6、§13.7）。
- 推论：多次 `reply` 调用每次各发一条；沉默（无 reply）与失败分别记录，不视为成功（§6）。
- 推论：`ToolContext`/`TurnContext` 增加可选 `channels`，`ToolSpec` 增加 `channel_param`，用于按本轮可用入口生成 reply 的 `channel` 枚举；与冻结契约的偏差需 lead 确认。
- 推论：会话行载荷（user/assistant/tool_call/tool_result/system_event）的字段约定为本切片自定，R2.2 与 R1.7 如需其他字段需对齐。
- 未决：工具结果附带新消息的具体载荷由 R2.2 收束（§13.2）；不默认新增最大轮数。模型请求的瞬时故障重试在供应商层（`[provider] retry_attempts`），循环本身不重试。
